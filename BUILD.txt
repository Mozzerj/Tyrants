Tyrants v4.0.14 DEV
Strategic AI Overhaul + Physical Command Network + Real Intelligence Tracking

Current development changes:
- Server truth and faction knowledge remain strictly separate.
- Enemy infantry, vehicles, aircraft, naval units and emplacements can become faction contacts only after observation.
- Human player cursor/optics observations are sent to a narrow server endpoint and validated for faction, range and line of sight.
- Connected physical UAVs can create visual contacts; AI force leaders and physical UAVs also gather intelligence from server-validated line of sight.
- Contacts store last-known position, direction, source, UTC observation time and identification state.
- Contact positions stop updating when sight is lost. Reacquisition updates the stored last-known state.
- Long-range sightings stay broad (for example INFANTRY or ARMOURED VEHICLE); close/optical/UAV observations can upgrade to exact type.
- Seeing enemy presence at a strategic location can update that faction's last-observed location ownership.
- Normal map now renders only faction-known enemy contacts, with age/staleness and identification labels.
- Faction contact knowledge and the intelligence event log persist in v4 saves.
- Developer Operations Console now includes FACTION INTEL MAP, INTELLIGENCE LOG and a manual runtime TEST TASK LIST.
- Full server autotest now verifies contact creation, redaction, frozen last-known position, identification upgrades, reobservation and intelligence logging.
- Manual debug tasks cover actual cursor/optics/UAV/map/save behaviours that require Arma runtime confirmation.

Deployment placement baseline:
- Reliable local-marker deployment sector colours retained.
- Exact-click HQ placement retained; no automatic relocation.
- HQ footprint remains 40 x 30 m.
- Roads, rail lines, power-line network objects and vegetation do not block HQ placement.
- Substantial buildings, walls, fences, rocks and similar physical obstructions remain blockers.

Method notes:
- TYRANTS_METHOD_NOTES.txt records proven, failed and current engine-specific approaches.


v4.0.11 developer testing additions:
- Restored direct Splendid Camera access from the Developer Operations Console.
- Splendid Camera is isolated from normal intelligence collection so debug flying does not reveal enemies to the faction.
- Added toggleable left-click teleporting on the embedded debug/intelligence maps.
- Added an in-console multiline command runner with LOCAL and SERVER execution.
- Enabled the standard Arma Debug Console for the host/logged-in admin in this DEV mission.
- Preserved v4.0.10 intelligence tracking, HQ placement and deployment behaviour.


v4.0.12 physical command network:
- Each active faction now has one physical named Main Commander and three physical named command officers.
- AI force leaders act as physical force commanders linked to the command hierarchy.
- New AI strategic operations enter COMMAND_PENDING and are delivered after a network-dependent propagation delay.
- Losing officers increases order delay; broken command routes reroute pending orders and restart their delivery delay.
- Main Commander death triggers a 30-second succession window before the highest-ranking surviving officer is promoted.
- Missing officers are replaced slowly (180s, 2 manpower each) while a functioning commander/HQ route remains.
- Total command loss causes COMMAND COLLAPSE. Existing delivered orders continue locally, while new strategic orders stop.
- A functioning HQ with 5 manpower can produce an emergency commander after 120s; otherwise sustained collapse reaches elimination at 240s.
- Victory now comes from sustained command collapse rather than killing the old accountant NPC.
- Own command personnel appear on the faction map; hostile command personnel still require real intelligence.
- Omniscient debug map shows commander/officer/force-command links, network status and pending orders.
- Debug console adds COMMAND NETWORK controls for teleporting to and killing command personnel during testing.
- Command personnel, network state and pending command orders persist in the v4 save journal.
- Debug COMMAND NETWORK panel includes a fast-forward timer action so succession/replacement/collapse timing can be tested without waiting several minutes.


v4.0.13 strategic AI overhaul:
- Replaced the one-objective commander loop with a 12-stage strategic decision pipeline.
- AI builds hostile decisions from faction-known locations/contacts rather than hidden server truth.
- Added emergency-defence, defensive, consolidate, probe, offensive, exploit and hold postures.
- Added candidate generation/scoring/validation for defend, reinforce, attack, exploit, recon, probe, raid, force generation, research and hold.
- Offensive validation preserves the configured strategic reserve instead of committing every free force.
- Contact raids use the last-known coordinate and are rejected/aborted when intelligence becomes too stale.
- Physical command degradation affects posture and all new force operations remain COMMAND_PENDING until routed/delivered.
- Added operation reassessment/abort logic and clearing of abandoned force waypoints.
- Added per-faction think locks to prevent overlapping scheduler/debug decisions.
- Added 12-node live debug flowchart with current-step/outcome/candidate validation highlighting.
- Added compact live trace polling so the flowchart does not spam the full omniscient-map payload.
- Omniscient debug map now shows strategic operation targets, reasons/scores/phases, force-to-target intent lines and pending commander/officer delivery routes with ETA/reroutes.
- Added AI_STRATEGIC_OVERHAUL.md and expanded runtime test guidance.

v4.0.14 debug console rewrite:
- Replaced the expanding accordion with a fixed five-page tool rail: Movement, AI, Command, Economy, System.
- Faction target controls remain pinned and workspace views are direct top tabs: Truth Map, AI Flow, Intel Map, Tests, Intel Log, Commands.
- Removed per-refresh ctrlSetPosition/ctrlCommit reflow of the left panel.
- Split status, tasks, log, command console and AI-flow rendering into targeted refresh functions.
- Full omniscient map payload now polls only while the Truth/Order map is visible; AI Flow uses compact trace-only updates; other views are event-driven.
- Full map refresh interval relaxed to 4 seconds and live AI trace interval to 0.55 seconds.
- Omniscient map culls individual live entities at wide zoom and infantry until closer zoom, reducing per-frame draw work while retaining force-level strategic markers.
